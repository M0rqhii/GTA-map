# GTA Map – plan wdrożenia

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Wspólna, synchronizowana na żywo mapa przeszukiwań GTA 5 dla organizacji, z publicznym zanonimizowanym podglądem, ukrytymi linkami logowania/rejestracji i panelem superadmina – wdrożona na Vercelu z backendem Supabase.

**Architecture:** Statyczne SPA (Vite + React + TS + Leaflet + Tailwind) na Vercelu. Cała logika uprawnień w Postgresie Supabase (RLS + funkcje `security definer`), zdarzenia na żywo wysyłane przez triggery bazy na prywatne kanały Realtime (`org:<id>:<channel_key>`, `pub:<id>`). Dwie Edge Functions do operacji wymagających service role (rejestracja, zarządzanie kontami).

**Tech Stack:** Node 24, Vite 7, React 19, TypeScript 5, react-router 7, @supabase/supabase-js 2, Leaflet 1.9, Tailwind 4 (@tailwindcss/vite), Vitest 3, Supabase (Postgres 17, Auth, Realtime, Edge Functions/Deno, pg_cron), Vercel CLI 54.

Specyfikacja: `docs/superpowers/specs/2026-09-29-gta-map-design.md` – każde zadanie implementuje jej odpowiednie sekcje.

## Global Constraints

- Obraz mapy 8192×8192 px, kafelki 256 px `public/tiles/{z}/{x}-{y}.webp`, zoom natywny 0–5, overzoom do 7.
- Kwadrat siatki = 64 px obrazu. Etykiety: kolumny Excel (A…Z, AA…), wiersze od 1: `K-42`.
- Paleta: dokładnie 80 kolorów hex małymi literami, identyczna w `src/lib/palette.ts` i w SQL (test to sprawdza).
- Nick `^[A-Za-z0-9_-]{3,20}$` (unikalny bez wielkości liter), hasło ≥ 8 znaków, nazwa organizacji 2–32 znaki po `trim` (unikalna bez wielkości liter), kod zaproszenia 6 znaków z `ABCDEFGHJKMNPQRSTUVWXYZ23456789`, tekst pinezki 1–300 znaków.
- Ikonki pinezek: `important ❗, found 📦, entrance 🚪, check ❓, danger ⚠️, note 💬`. Limit 500 pinezek/organizację.
- Opóźnienie publiczne ∈ {0, 5, 15, 30} min. Retencja: `activity` 30 dni, `cell_events` 1 h.
- Limity: rejestracja 5/h/IP, `join_org` 10/10 min, `create_org` 5/h, kwadraty 3000/min, pinezki 30/min.
- Każda funkcja SQL: `security definer`, `set search_path = ''`, w pełni kwalifikowane nazwy. Tabele i funkcje wewnętrzne w schemacie `private` (niewystawionym przez API).
- Teksty użytkowników renderowane wyłącznie jako tekst (React / `textContent`), nigdy `innerHTML`.
- Syntetyczny e-mail: `<nick małymi literami>@users.invalid`.
- UI w języku polskim. Kod, nazwy i komentarze po angielsku.
- Commity kończą się linią `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

**Files:** Create `supabase/migrations/0001_schema.sql` (i zastosuj `apply_migration`).

**Produces (SQL):**
- Schemat `private`; `grant usage on schema private to anon, authenticated`.
- `alter default privileges for role postgres in schema public revoke execute on functions from public, anon, authenticated;` (i to samo dla `private`) – każde uprawnienie nadawane jawnie.
- `private.palette() returns text[] immutable` z literałem między `-- PALETTE-BEGIN` a `-- PALETTE-END`.
- Tabele `public.organizations`, `public.profiles`, `public.cells`, `public.pins`, `public.activity` dokładnie jak w specyfikacji + `organizations.channel_key text not null default encode(extensions.gen_random_bytes(16),'hex')`; check `name !~ '[[:cntrl:]]'`; check `cells.x between 0 and GRID_COLS-1`, `y between 0 and GRID_ROWS-1`; pins `px, py between 0 and 8192`, `body !~ '[\x01-\x09\x0b-\x1f\x7f]'`; `unique index on lower(name)`, `unique index on lower(username)`; indeksy: `cells(org_id, user_id)`, `pins(org_id)`, `activity(org_id, id desc)`, `profiles(org_id)`.
- Tabele `private.cell_events`, `private.access_paths`, `private.rate_limits` (jak w specyfikacji).
- Helpery (`security definer`, `stable`, `search_path=''`, `grant execute to authenticated` – oraz `anon` tam gdzie potrzebne w politykach realtime):
  `private.my_org_id() returns uuid` (org aktywnego użytkownika), `private.is_superadmin() returns boolean`,
  `private.org_topic(p_org uuid) returns text` = `'org:'||id||':'||channel_key`,
  `private.hit_rate_limit(p_bucket text, p_max int, p_window interval, p_cost int default 1)` – okno stałe, `raise exception 'rate_limited'` po przekroczeniu,
  `private.new_invite_code() returns text` (6 znaków z alfabetu, pętla do unikalności), `private.new_access_path(p_prefix text) returns text` (`p_prefix || '-' || 20 znaków [A-Za-z0-9]` z `gen_random_bytes`).
- Trigger `private.handle_new_user()` `after insert on auth.users`: nick z `raw_user_meta_data->>'username'` gdy pasuje do wzorca, inaczej z `full_name`/`name`/`user_name` oczyszczony `[^A-Za-z0-9_-]`, obcięty do 16, min 3 (inaczej `gracz`), sufiks 4 cyfr przy kolizji; `activated := coalesce((raw_app_meta_data->>'activated')::boolean,false)`; **jeśli `raw_app_meta_data->>'provider' = 'email'` i nie `activated` → `raise exception 'signup_disabled'`** (blokuje publiczne `/auth/v1/signup`).
- RLS: `enable row level security` na wszystkich tabelach `public` i `private`. Polityki SELECT (tylko `authenticated`):
  - `organizations`: `id = (select private.my_org_id()) or (select private.is_superadmin())`
  - `profiles`: `id = auth.uid() or (org_id is not null and org_id = (select private.my_org_id())) or (select private.is_superadmin())`
  - `cells`, `pins`, `activity`: `org_id = (select private.my_org_id()) or (select private.is_superadmin())`
- Uprawnienia: `revoke all on all tables in schema public from anon, authenticated;` następnie `grant select (id, name, owner_id, is_public, public_delay_minutes, channel_key, created_at) on public.organizations to authenticated;` `grant select (id, username, org_id, color, joined_at, created_at) on public.profiles to authenticated;` `grant select on public.cells, public.pins, public.activity to authenticated;` Brak INSERT/UPDATE/DELETE dla klientów.
